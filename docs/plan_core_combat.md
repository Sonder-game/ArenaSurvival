# План реализации: Базовый Боевой Цикл

Этот документ описывает план реализации базовой боевой механики в соответствии с существующей архитектурой Entity-Component-System (ECS).

## 1. Определение новых компонентов

Необходимо расширить файл `packages/client/src/ecs/components.ts`, добавив следующие компоненты:

- **`HealthComponent`**:
  - `currentHealth`: number - текущее здоровье сущности.
  - `maxHealth`: number - максимальное здоровье.

- **`DamageComponent`**:
  - `damage`: number - урон, который наносит сущность (например, снаряд).

- **`VelocityComponent`**:
  - `direction`: Vector3 - нормализованный вектор направления движения.
  - `speed`: number - скорость движения.

- **`CollidableComponent`**:
  - `type`: 'enemy' | 'projectile' | 'player' - тип сущности для определения логики столкновений.
  - `size`: number - радиус сферы для проверки столкновений.

- **`EnemyComponent`**:
  - Компонент-тег для идентификации врагов.

- **`ProjectileComponent`**:
  - Компонент-тег для идентификации снарядов.

## 2. Создание новых систем

В файле `packages/client/src/ecs/systems.ts` нужно реализовать логику в виде новых систем:

- **`PlayerInputSystem`**:
  - **Задача**: Отслеживать ввод пользователя (клик левой кнопкой мыши).
  - **Логика**:
    1. При клике определять координаты курсора на 3D-плоскости.
    2. Создавать новую сущность-снаряд (`Projectile`).
    3. Рассчитывать вектор направления от игрока к курсору.
    4. Добавлять снаряду `VelocityComponent` с рассчитанным направлением и скоростью.

- **`MovementSystem`**:
  - **Задача**: Двигать сущности, имеющие `VelocityComponent`.
  - **Логика**:
    1. В каждом кадре (`update`) для всех сущностей с `VelocityComponent` и `TransformNode` (или аналогичным компонентом для позиции):
    2. Обновлять позицию сущности по формуле: `position += direction * speed * deltaTime`.

- **`CollisionSystem`**:
  - **Задача**: Обнаруживать и обрабатывать столкновения.
  - **Логика**:
    1. В каждом кадре получать все сущности с `CollidableComponent`.
    2. Для каждой пары "снаряд-враг" проверять расстояние между их центрами.
    3. **Условие столкновения**: `distance(projectile, enemy) < projectile.size + enemy.size`.
    4. **При столкновении**:
       - Получить `DamageComponent` у снаряда и `HealthComponent` у врага.
       - Уменьшить `currentHealth` врага на величину `damage`.
       - Удалить сущность-снаряд из мира.

- **`DeathSystem`**:
  - **Задача**: Обрабатывать "смерть" сущностей.
  - **Логика**:
    1. В каждом кадре проверять все сущности с `HealthComponent`.
    2. Если `currentHealth <= 0`:
       - Удалить 3D-модель сущности со сцены.
       - Удалить саму сущность из мира ECS.

## 3. Фабрики для создания сущностей

Нужно будет создать функции (фабрики) для удобного создания врагов и снарядов.

- **`createEnemy(position)`**:
  - Создает новую сущность.
  - Добавляет компоненты:
    - `TransformNode` с 3D-моделью куба.
    - `HealthComponent` (например, `health: 100`).
    - `CollidableComponent` (`type: 'enemy'`, `size: 1`).
    - `EnemyComponent`.

- **`createProjectile(position, direction)`**:
  - Создает новую сущность.
  - Добавляет компоненты:
    - `TransformNode` с 3D-моделью маленькой сферы.
    - `DamageComponent` (например, `damage: 10`).
    - `VelocityComponent` (с переданными `direction` и скоростью).
    - `CollidableComponent` (`type: 'projectile'`, `size: 0.2`).
    - `ProjectileComponent`.

## 4. Интеграция в игровой цикл

В файле `packages/client/src/Game.ts` необходимо зарегистрировать и вызывать новые системы в правильном порядке в главном цикле `update()`:

1. `PlayerInputSystem` (обработка ввода)
2. `MovementSystem` (обновление позиций)
3. `CollisionSystem` (проверка столкновений)
4. `DeathSystem` (проверка смертей)
5. Рендеринг сцены (уже должен быть).
