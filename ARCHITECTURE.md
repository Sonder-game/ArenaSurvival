# Архитектура игры "Vampire Survivors Clone"

Этот документ описывает архитектуру и план реализации сетевой игры, похожей на Vampire Survivors.

## Обзор

Игра будет состоять из трех основных модулей:

*   **`@hero-survival/shared`**: Общий код, используемый клиентом и сервером. В основном, это определения типов данных для сетевого взаимодействия.
*   **`@hero-survival/server`**: Серверная часть, отвечающая за игровую логику, обработку подключений и синхронизацию состояния.
*   **`@hero-survival/client`**: Клиентская часть, отвечающая за отрисовку игрового мира, обработку пользовательского ввода и взаимодействие с сервером.

## План реализации

### Шаг 1: Рефакторинг общего кода (`@hero-survival/shared`)

1.  **Определить структуры данных (DTO):**
    *   `Vector2`: `{ x: number, y: number }` для позиции и направления.
    *   `PlayerState`: `{ id: string, position: Vector2 }`
    *   `EnemyState`: `{ id: string, position: Vector2 }`
    *   `GameState`: `{ players: PlayerState[], enemies: EnemyState[] }`

2.  **Определить типы сетевых сообщений:**
    *   **От клиента к серверу:**
        *   `PlayerInput`: `{ type: 'playerInput', payload: { direction: Vector2 } }` - для отправки направления движения игрока.
    *   **От сервера к клиенту:**
        *   `GameStateUpdate`: `{ type: 'gameStateUpdate', payload: GameState }` - для отправки полного состояния игры.

### Шаг 2: Реализация основной логики на сервере (`@hero-survival/server`)

1.  **Создать игровой цикл (game loop):**
    *   Использовать `setInterval` для обновления состояния игры с фиксированной частотой (например, 60 раз в секунду).

2.  **Реализовать управление состоянием игры:**
    *   Хранить `GameState` в памяти.
    *   При подключении нового клиента - создавать для него `PlayerState` и добавлять в `GameState`.
    *   При отключении - удалять `PlayerState`.
    *   При получении `PlayerInput` - обновлять позицию соответствующего игрока.

3.  **Добавить логику врагов:**
    *   Реализовать простой спавн врагов (например, каждые несколько секунд).
    *   Каждый враг должен двигаться в сторону ближайшего игрока.

4.  **Организовать рассылку состояния:**
    *   Использовать `setInterval` для рассылки `GameStateUpdate` всем подключенным клиентам (например, 20 раз в секунду).

### Шаг 3: Реализация логики на клиенте (`@hero-survival/client`)

1.  **Переработать сетевой код:**
    *   Реализовать обработку сообщения `GameStateUpdate`.
    *   При получении нового состояния, обновлять локальное представление игрового мира.

2.  **Реализовать отображение:**
    *   Удалить текущий вращающийся куб.
    *   Создавать/удалять/обновлять 3D-объекты (сферы для игроков, кубы для врагов) на основе `GameState`.

3.  **Обработка пользовательского ввода:**
    *   Отслеживать нажатия клавиш WASD.
    *   Формировать `PlayerInput` и отправлять на сервер при каждом изменении направления.
